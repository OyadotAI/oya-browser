# Chrome DevTools Protocol on Mars

Generated by `mars-mdp --matrix` from the pinned protocol definitions (Chromium `2c592105bbcd9490a9894df48d0fe59b2c512651`, V8 `fedd021b538607860f9c56e5c193ad8dcd4f2bb1`, protocol 1.3). Do not edit by hand; `cargo test -p mars-mdp` checks it.

Every method is answered natively: a Mars native operation (`page.*`, `tab.*`, `control.*`) under the same ownership, epoch and redaction rules as MCP. Mars has no debugger and proxies nothing to an engine; a method it does not translate gets an explicit error.

## Where Mars differs

- **Ownership.** Every mutation (navigation, input, script evaluation, attribute writes, cookies, emulation) carries the control epoch this connection observed. When the person takes a tab back, the next mutation fails with `control_denied: ...`; reads keep answering. An evaluation on a tab the connection does not hold runs in place and keeps nothing, so its remote objects do not outlive the call.
- **One realm per page.** `Page.createIsolatedWorld` announces a context, but it shares the page's realm with the main world: a client's objects are visible to page scripts of the same page. Scripts registered with `Page.addScriptToEvaluateOnNewDocument` run right after each commit, after the page's own scripts.
- **Client code is page code.** Evaluated expressions and function declarations are appended to the page's script list, compiled at a stable offset, and dropped again when they left no live function or global behind. They never count against the page's own `eval` budget.
- **Navigations commit whole.** Every event of a navigation (request, response, frameNavigated, contexts, lifecycle through `networkIdle`) is sent before the command's answer. Subresource requests are not reported on the Network domain, and `Fetch` pauses navigation requests only: a `fetch()` or image inside the page cannot be intercepted yet (it needs a pause point in the runtime's script-request path).
- **Geometry is Eye's.** `DOM.getBoxModel`, `getContentQuads` and `scrollIntoViewIfNeeded` answer from the painted display. `getBoundingClientRect`, `elementFromPoint`, `offsetWidth` and `document.activeElement` inside V9 still answer without layout or focus, so Playwright's default actionability checks (visible, receives events) time out; `force: true`, `state: 'attached'` and Puppeteer's point-based clicks work. Input.insertText goes to the node a click or `DOM.focus` focused, else to the element the client last passed to `Runtime.callFunctionOn`.
- **Shared viewport.** `Emulation.setDeviceMetricsOverride` and `setEmulatedMedia` change the browser's one viewport and colour scheme, for every tab. `setUserAgentOverride`, `setTimezoneOverride` and `setLocaleOverride` change what the page's scripts read from the next step on; the request headers Relay sends are unchanged, and `Network.setExtraHTTPHeaders` is recorded, not sent.
- **Screenshots** are PNG, of the viewport or a clip cut from it. **Cookies** are listed with HttpOnly values for the client, as Chrome does; page scripts never see them.
